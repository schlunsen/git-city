Guide

Customize your city

Git City builds an island from every GitHub profile automatically. With one small JSON file you take over the parts you care about. Developers set up the island in their profile repository, organizations in their .github repository. Maintainers style a repository's building in the repository itself.

Profile level
<login>/<login>/.git-city/city.json
<org>/.github/.git-city/city.json
Your whole island: its name and welcome message, biome, city shape, landmarks, the look (light, weather, TV / FX, your time zone), neighbours, which repositories lead or hide, every building, the player's music and your plane.
Repo level
<owner>/<repo>/.git-city/building.json
One repository's building: graffiti on its walls, the roof, neon windows, a flag, the facade colour, its silhouette, the shop sign and billboard text. The owner's city.json wins, field by field.

Profile level

Your island: city.json

The file lives in your profile repository: the public repository named exactly like your login (the one that shows your profile README). An organization keeps it in its .github repository instead — <org>/.github/.git-city/city.json — and everything on this page works the same way.

  1. Have a profile repository. Create a public repository named exactly <your login> if you don't have one yet (for an organization: a public repository named .github). GitHub's guide.
  2. Add .git-city/city.json on its default branch. Start with the minimal example below, or press Customize in your city and let Git City write it for you.
  3. Reload your city after about 5 minutes (?user=<login>). GitHub's CDN caches the file for up to 5 minutes.

.git-city/city.json

{
  "$schema": "https://schlunsen.github.io/git-city/schema/city-config.v1.json",
  "version": 1,
  "island": { "name": "Octo Isle", "biome": "tropical" },
  "welcome": "Welcome to my city!",
  "featured": ["my-best-repo"]
}

.git-city/city.json

{
  "$schema": "https://schlunsen.github.io/git-city/schema/city-config.v1.json",
  "version": 1,
  "island": { "name": "Schlunsen Isle", "biome": "tropical", "shape": "round" },
  "welcome": "Welcome to the island of broken builds",
  "look": {
    "accent": "#8c78ff", "time": "auto", "weather": "snow",
    "tv": false, "fx": true, "timezone": "Europe/Copenhagen"
  },
  "landmarks": ["rollerCoaster", "observatory", "campsite"],
  "neighbours": ["gaearon", "antfu", "sindresorhus"],
  "featured": ["git-city", "gource-view"],
  "hide": ["dotfiles"],
  "repos": {
    "git-city": {
      "style": "tower", "color": "#64dedb", "sign": "you are here",
      "graffiti": { "text": "ship it!", "color": "#ff5ab4", "style": "bubble" },
      "roof": "helipad", "neon": "#8c78ff", "flag": "🏙️"
    },
    "gource-view": { "billboard": "Watch your repo grow" }
  },
  "player": { "music": "cipher", "volume": 20 },
  "plane": { "color": "#e4574f", "name": "Spirit of Rebase" }
}

Every field is optional; anything you leave out stays automatic. Unknown keys are ignored (with a warning), so a typo never breaks your city. With the $schema line, editors like VS Code validate and autocomplete the file.

Repo level

A building: building.json

Maintainers can give a repository's building some personality from inside the repository. It appears in the owner's city, and Git City reads it for the 16 most-starred buildings on screen, and for any building someone clicks.

  1. Add .git-city/building.json to the repository's default branch (example below). In Git City, Customize › Repositories › edit › Copy as building.json writes one for you.
  2. Commit it. The repository must be public, not a fork and not archived (those don't get buildings).
  3. Open the owner's city after about 5 minutes and look for the building (clicking it also fetches the file straight away).

.git-city/building.json

{
  "$schema": "https://schlunsen.github.io/git-city/schema/building-config.v1.json",
  "version": 1,
  "graffiti": { "text": "ship it!" }
}

.git-city/building.json

{
  "$schema": "https://schlunsen.github.io/git-city/schema/building-config.v1.json",
  "version": 1,
  "graffiti": { "text": "ship it!", "color": "#ff5ab4", "style": "bubble" },
  "roof": "garden",
  "neon": "#8c78ff",
  "flag": "🏴‍☠️",
  "style": "stepped",
  "color": "#e4574f",
  "sign": "open 24/7",
  "billboard": "The fastest way to ship"
}
Precedence: the owner wins, field by field. If the owner's city.json has repos["<repo>"], each field set there beats the same field in building.json. For example, if the repository sets roof and graffiti and the owner sets roof and color, the building gets the owner's roof and colour and the repository's graffiti. The owner can also hide the repository entirely.
No typing needed

The Customize button and one-click Publish

  1. Open your city and press Customize in the toolbar (in the ☰ menu on phones). The panel says whether your city.json was found, loaded or partly ignored.
  2. Edit and watch. With Live preview on, every change is applied to the island around you. The draft goes through exactly the same validation as a published file, and the JSON updates below the form, with any warnings. Revert drops the draft.
  3. Publish. Git City opens GitHub's own editor in a new tab. It never uses tokens or OAuth. With no file yet, you get GitHub's "new file" page with .git-city/city.json already filled in. If the file exists, GitHub can't pre-fill it: press Copy JSON, then Edit city.json on GitHub, paste over the contents, and commit.

Anyone can open the panel on any city and try ideas; only someone who can commit to the profile repository (or the organization's .github) can save the result.

Updates

Caching

  • Both files are read from raw.githubusercontent.com (your default branch), not the GitHub API, so they never use up the 60-requests-an-hour budget.
  • GitHub's CDN caches them for up to 5 minutes. A hard reload doesn't skip that cache.
  • A city waits at most 4 seconds for city.json. If it's slower, the automatic city appears first and your settings follow as soon as the file arrives. building.json gets 3 seconds and never holds a city back.
  • A missing file (404) is simply the automatic look. Your browser may log each 404 in its console; that's normal.
Help

Troubleshooting

A notice says "city.json ignored: …"
The file exists but can't be used at all: invalid JSON (the notice says where), larger than 32 KB, or not a JSON object. Fix it, commit, wait up to 5 minutes. The same notice appears in Customize and in the browser console.
A notice says "city.json: N settings ignored"
The file loaded, but some fields were dropped (a misspelt key, a colour like red, a repository that isn't yours). Open Customize for the list, or the browser console, where each one is logged with its reason. Problems in a building.json are logged in the console ([git-city] owner/repo/.git-city/building.json: …).
Nothing changes
Wait out the 5-minute cache. Check the path is exactly .git-city/city.json (or building.json) on the default branch, and that the repository is public and, for city.json, named exactly like your login.
A landmark is missing
Landmarks are best effort: each needs a free site of the right kind (the roller coaster needs the big fairground, wind turbines a hillside). Try another biome or fewer landmarks.
My building.json is ignored
The owner's city.json may set the same fields (the owner wins), the repository may be hidden, a fork or archived, or the building isn't among the 16 most-starred: click it in the city to load its file.
Security & privacy

What Git City does with your file

  • Data only, never code. The files are read with JSON.parse and nothing else. No scripts, no templates, no HTML.
  • A strict whitelist. Only the fields above are read. Names come from fixed lists, colours must be #rrggbb, numbers are clamped, logins and repository names are checked, and files over 32 KB (city.json) or 16 KB (building.json) are ignored unread.
  • Your text is yours, and it stays text. There is no content moderation. Text only ever reaches the page as painted pixels (signs, graffiti, the plane) or plain text (the profile card), never as HTML.
  • No external URLs. No field is a URL, and Git City never loads an image, font, frame or link named in a config. Avatars come from github.com. Pictures shown from a repository's README during the tour are only taken from GitHub's own image hosts (raw.githubusercontent.com, user-images, private-user-images, camo.githubusercontent.com, github.com).
  • Defence in depth. The app runs under a strict Content-Security-Policy. Scripts come only from Git City itself and the three.js CDN, and data only from GitHub.
  • Nothing is written for you. Publishing opens GitHub's own editor; Git City never sees a token, and you commit the file yourself.
